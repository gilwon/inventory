# Spec: 라벨 출력 형식 선택(바코드 또는 QR)
Source: intent.md (Status: draft)

## Requirements
- R1 `/labels` 선택 화면에 "출력 형식"(QR, 바코드) 선택이 있고 기본은 QR이다. 선택은 라벨 만들기 요청에 실려 간다. 키보드로 고를 수 있고 선택 상태가 글자로도 드러난다.
- R2 QR을 고르면 지금과 같은 라벨이 나온다(QR + 이름 + 코드 글자).
- R3 바코드를 고르면 라벨은 Code128 바코드 + 이름 + 코드 글자이며, 바코드는 흰 바탕에 검정, 인쇄 가능한 크기로 A4 3열 격자 한 칸(63.33mm x 34mm)에 들어간다.
- R4 바코드로 만들 수 없는 코드(ASCII 32~126 밖의 문자가 있거나 24자를 넘는 코드)가 하나라도 있으면 라벨을 만들지 않고 해당 코드를 최대 5개까지 보여 주며 "QR로 바꾸거나 해당 항목을 빼 주세요" 취지의 오류를 보인다.
- R5 형식이 바뀌면 이미 만든 미리보기를 지우거나 다시 만들어 형식이 섞이지 않게 한다.
- R6 서버는 형식 값을 `"qr" | "barcode"`만 받고 그 외 값은 거절한다.
- R7 인쇄 스타일과 메뉴 숨김, 120개 상한, 로그인 확인은 바뀌지 않는다.

## Design
- 서버 `buildLabels(itemIds, locationIds, format)`가 형식별 SVG를 만든다. 바코드는 `bwip-js`의 `toSVG`(Code128, 서버 전용 import)로 만든다. 클라이언트 번들에 넣지 않는다.
- 선택은 Lucian 세그먼트(`src/components/lucian/segmented.tsx`)를 쓰고 라벨 만들기 버튼 위에 둔다.
- 라벨 칸 레이아웃은 바코드일 때만 세로(바코드 위, 글자 아래)로 바꾸는 CSS 변형 클래스를 쓴다.

## Decisions
- 규격은 Code128로 한다. SKU가 자유 문자열이어서 숫자 전용 규격(EAN)이 맞지 않고, 앱 스캐너(ZXing)가 읽을 수 있다.
- 한글 등 ASCII 밖 문자는 Code128로 표현할 수 없으므로 R4처럼 만들기를 막고 안내한다(조용히 건너뛰지 않는다). 이유는 일부 라벨이 빠진 인쇄물을 모르고 쓰는 것이 더 위험해서다.
- 24자 상한은 칸 너비 약 55mm에서 모듈 폭 0.19mm 이상(스캔 가능 하한)을 지키기 위한 값이다.
- `bwip-js` 의존성 1개를 추가한다. 직접 인코더를 짜는 것보다 안전하다.

## Conflicts
- `intent/2026-10-26-inventory-phase2/spec.md` R27(라벨은 QR)과 D14(라벨 형식 선택 기능은 넣지 않는다)를 이 요청이 바꾼다. 같은 커밋에서 R27에 "QR 또는 바코드(출력 형식 선택)"를 반영한다. D14는 크기 선택에 관한 결정이라 크기는 계속 A4 3열 한 가지다.

## Acceptance
- 바코드를 골라 만들면 Code128 바코드 라벨이 A4 격자로 나오고 인쇄 미리보기에서 메뉴가 숨는다.
- 앱 스캔 화면에서 화면에 띄운 바코드 라벨이 읽혀 같은 품목·위치로 해석된다(가능하면 확인, 아니면 미확인 명시).
- 한글 SKU 품목을 고르고 바코드를 누르면 오류 문구가 나오고 라벨이 만들어지지 않는다. QR로 바꾸면 만들어진다.
