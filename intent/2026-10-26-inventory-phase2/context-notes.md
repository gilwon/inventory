# Context Notes: 재고 관리 웹앱 2차
결정과 이유를 발생한 순서대로 이어서 적는다. 기각한 대안도 남긴다.

## 2026-10-26 문서 단계
- 사용자 선택. 계정 생성은 Edge Function. 기각한 안은 Supabase 대시보드 수동 생성(앱에서 초대 불가)과 앱 서버에 서비스 롤 키 저장(키가 Vercel 환경변수에 들어감).
- 사용자 선택. 권한 차이는 1차 spec R4 안 그대로 확정. 기각한 안은 작업자의 조정·정정까지 막는 안.
- 이메일 초대는 기각. 임시 비밀번호를 관리자가 전달한다. 메일 발송 설정과 재설정 화면이 필요 없다.
- 실사는 한 트랜잭션. 기각한 안은 행별 부분 성공.
- 스캔 라이브러리는 iOS Safari를 고려해 JS 디코더를 쓰고 BarcodeDetector에만 기대지 않는다. 구체 패키지는 Worker가 고르고 이유를 보고한다.
- 계정 비활성화는 이번에 넣지 않는다(intent 열린 질문).
- 승인 절차. intent·spec·plan 세 문서는 사용자가 한 번에 승인했다("승인"). 1차 후속 Worker(Database 제네릭 등)는 1차 plan 범위라 문서 승인과 무관하게 먼저 진행한다.
