# Spec: Lucian UX/UI 적용
Source: intent.md (Status: approved)

## Requirements
- U1 `--ux-*` 토큰(라이트·다크)을 앱의 전역 테마로 쓴다. Tailwind 테마 색(`surface`, `ink`, `line`, `accent` 등)이 토큰을 가리키고, 화면의 zinc·blue·`dark:` 색 클래스를 이 색으로 바꾼다. 다크는 토큰이 바꾸므로 `dark:` 색 변형을 쓰지 않는다.
- U2 버튼, 입력, 카드, 알림, 표, 배지의 공통 스타일이 한 곳(`items/common.ts`의 상수와 `globals.css`)에 있고 모든 화면이 쓴다.
- U3 내비게이션. 데스크톱은 펼쳐지는 사이드 레일(#040), 모바일은 하단 탭 바(#041)를 반응형으로 이식한다. 현재 경로 표시, 키보드 조작, 더보기 메뉴(가져오기/내보내기 등)를 유지한다.
- U4 로그인 화면은 로그인 카드(#062)를 이식한다. 실제 로그인 Server Action과 연결하고, 실패 시 카드가 흔들리며 서버가 준 오류 문구를 보인다. 비밀번호 보기 버튼을 둔다.
- U5 입출고 화면의 유형 탭(입고·출고·이동·조정)은 세그먼트 컨트롤(#047의 세그먼트 부분 또는 #039)로 바꾼다. 기록 성공·실패 메시지는 토스트(#070)로 보인다. 입력 중 값과 한 화면 입력 흐름(R35)은 그대로다.
- U6 대시보드 요약 카드의 숫자는 자리별로 굴러가는 표시(#098의 숫자 부분)를 쓴다. 값이 같으면 움직이지 않는다.
- U7 빈 상태(목록 없음, 검색 결과 없음)는 일러스트가 있는 빈 상태(#092 또는 #088)로, 데이터를 불러오는 중에는 스켈레톤(#079)을 Suspense fallback으로 쓴다. 오류 표시는 인라인 알림(#072)을 쓴다.
- U8 모든 모션은 `prefers-reduced-motion: reduce`에서 최종 상태로 즉시 끝나고 기능은 그대로다.

## Design
- 이식 방식. Lucian 요소의 CSS는 일반 CSS 파일로 두고(`.uNNN` 범위, Tailwind로 재작성하지 않음) 컴포넌트가 `import`한다. 고정 크기 요소는 `max-width:100%`와 폭 100%로 반응형 보정하고 그 사실을 보고한다. 스크립트는 React 이펙트로 옮기며 모든 리스너·타이머를 정리한다.
- 토큰 연결. `globals.css`에 `tokens` 결과의 `--ux-*`를 두고(앱 테마와 같은 이름 규칙), `@theme inline`으로 Tailwind 색을 토큰에 연결한다. 폰트는 앱의 한글 폰트 스택을 유지하고 `.ux{font-family:inherit}`로 맞춘다.
- 공통 컴포넌트. `src/components/lucian/`에 이식 컴포넌트를 둔다(각 파일 첫 줄 라이선스 주석, 이어서 역할 주석).
- 적용 순서. 토큰·공통 스타일 → (내비 | 로그인·입출고·대시보드·빈 상태·스켈레톤) 병렬 → 2차 화면은 이 토큰과 컴포넌트로 만든다.

## Decisions
- D1 라이브러리의 보라 강조색(#6A57F2, 다크 #B7A4FF)을 그대로 쓴다. 기각한 안은 재고 앱용 별도 색. 이유는 요청이 라이브러리 적용이다.
- D2 라이브러리 요소 중 데이터 화면(표, 이력 목록, 폼 입력)에는 모션 요소를 넣지 않고 토큰 스타일만 적용한다. 이유는 intent의 데이터 우선 제약이다.
- D3 Tailwind로 요소 CSS를 다시 쓰지 않는다. 이유는 라이브러리 이식 규칙(모션 값 보존).
- D4 `dark:` 변형 제거로 다크 모드 판정은 토큰(`prefers-color-scheme`과 `data-theme`)이 맡는다. 사용자 요청(2026-10-26)으로 시스템·라이트·다크 전환 버튼을 둔다. 기본은 시스템이고 선택은 브라우저(localStorage `theme`)에 저장하며 `<html data-theme>`로 적용한다. 시스템을 고르면 속성을 지워 `prefers-color-scheme`이 정한다.

## Conflicts
- 전역 규약(`design-quality-check`)의 480/1024/1440 확인과 1차 R34의 360px가 모두 대상이다. 둘 다 확인한다.
- 1차 plan의 공통 규약 중 "다크 모드 대비(`dark:`) 클래스를 붙인다"는 이 변경으로 "토큰 색을 쓴다"로 바뀐다. 이 spec 승인 후 1차 plan 공통 규약에 이탈로 적는다.

## Acceptance
1. 모든 화면이 토큰 색을 쓰고 라이트·다크 둘 다 글자 대비가 AA 이상이다(주요 조합 측정).
2. 360px, 480px, 1024px, 1440px에서 가로 스크롤과 잘림이 없다.
3. 데스크톱에서 사이드 레일, 모바일에서 하단 탭 바가 동작하고 현재 화면이 표시된다. 키보드로 이동하고 포커스 링이 보인다.
4. 로그인에서 틀린 비밀번호를 넣으면 카드가 흔들리고 오류 문구가 보이며, 맞으면 대시보드로 이동한다.
5. 입고를 기록하면 토스트가 보이고 수량 입력 값이 비워진다. 초과 출고는 기존처럼 제출이 막힌다.
6. 대시보드 숫자, 빈 목록, 로딩 스켈레톤이 보이고 모션 줄이기 설정에서는 즉시 최종 상태가 된다.
7. 기능 회귀가 없다. 1차 Acceptance 1~11의 핵심 흐름(입고·출고·이동·정정·조정, 가져오기·내보내기)이 그대로 된다.
8. 각 이식 파일 맨 위에 요소별 MIT 라이선스 주석이 있다.
