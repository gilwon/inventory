# Spec: 재고 관리 웹앱
Source: intent.md (Status: approved)
Status: approved. C1(1차에 단건 조정 포함), D7(가져오기 오류 시 전체 거절) 승인됨.

## Requirements
번호 뒤 [1]은 1차, [2]는 2차 범위이다.

### 인증·권한
- R1 [1] 이메일+비밀번호로 로그인한다. 로그인하지 않으면 로그인 화면 외 모든 화면과 데이터 접근이 막힌다.
- R2 [1] 외부인의 자가 가입은 불가능하다. 첫 계정은 운영자가 인증 대시보드에서 만들고 관리자 권한을 가진다.
- R3 [1] 사용자 프로필에 권한(관리자/작업자)을 저장한다. 1차에서는 모든 로그인 사용자가 모든 기능을 쓴다.
- R4 [2] 관리자가 사용자를 초대한다. 작업자는 품목·위치의 생성/수정/보관, 엑셀 가져오기, 사용자 관리를 할 수 없고 나머지는 할 수 있다.

### 위치
- R5 [1] 위치는 상위-하위 트리이다. 위치마다 코드(전체에서 유일, 대소문자 무시)와 이름이 있다. 최상위 위치가 창고 역할을 한다.
- R6 [1] 위치 목록은 트리로 보이고, 코드로 검색할 수 있다. 위치를 고르면 그 위치의 품목별 수량이 보인다.
- R7 [1] 위치를 보관 처리하면 새 입력의 선택지에서 빠진다. 수량이 남은 품목이 있거나 활성 하위 위치가 있으면 보관할 수 없다.
- R8 [1] 위치는 자기 하위로 옮길 수 없다(순환 금지).

### 품목
- R9 [1] 품목은 SKU(직접 입력, 앞뒤 공백 제거, 대소문자 무시 유일), 이름, 바코드(선택, 대소문자 무시 유일), 단위, 최소 수량(정수, 기본 0), 메모, 사진 1장을 가진다.
- R10 [1] 품목 검색은 SKU, 이름, 바코드의 부분 일치를 지원하고 정확히 일치하는 SKU·바코드를 먼저 보여준다.
- R11 [1] 품목 상세에 위치별 수량과 합계, 해당 품목의 이력이 보인다.
- R12 [1] 품목을 보관 처리하면 새 입력의 선택지에서 빠진다. 위치 어디에든 수량이 남아 있으면 보관할 수 없다.
- R13 [1] 사진은 이미지 파일 1장, 5MB 이하이다. 비공개 저장소에 두고 로그인한 사용자에게만 보인다.

### 수량·이력
- R14 [1] 수량은 정수이다. 품목×위치별 수량을 저장하고 품목 합계는 조회 시 계산한다.
- R15 [1] 수량 변경은 입고, 출고, 이동, 조정 이력 입력으로만 일어난다. 이력 행은 증감(delta), 유형, 사유, 작업자, 시각(UTC)을 가진다.
- R16 [1] 이동은 출발 위치 감소와 도착 위치 증가가 한 트랜잭션으로 일어나고, 두 이력 행이 같은 묶음 ID를 가진다.
- R17 [1] 어떤 입력도 품목×위치 수량을 음수로 만들 수 없다. 만들려는 입력은 오류로 거절되고 아무것도 저장되지 않는다.
- R18 [1] 이력은 수정·삭제할 수 없다. 잘못된 입력은 정정 기능이 반대 방향 이력을 추가해서 고친다. 정정 이력은 원본을 가리키고, 원본 하나당 정정은 한 번만 가능하다. 정정으로 음수가 되면 거절된다.
- R19 [1] 이력 목록은 기간, 품목, 위치, 유형, 작업자로 거를 수 있고 최신순이다.
- R20 [1] 수량 컬럼과 이력은 항상 일치한다. 각 품목×위치 수량은 해당 이력 증감의 합과 같다.
- R21 [1] 조정 입력은 품목, 위치, 실제 수량, 사유(필수)를 받아 현재 수량과의 차이를 조정 이력으로 기록한다. 차이가 0이면 기록하지 않는다. (충돌 항목 C1 참고)
- R22 [2] 실사 화면은 위치를 고르면 그 위치의 품목을 모두 나열하고, 실제 수량을 입력한 행만 R21 방식으로 일괄 조정한다. 사유는 행마다 필수이다.

### 대시보드
- R23 [1] 첫 화면에 검색창, 최근 이력 10건, 활성 품목 수와 활성 위치 수가 보인다.
- R24 [2] 첫 화면에 부족 품목 목록(합계 수량 < 최소 수량, 최소 수량 0 초과인 품목)이 보인다. 이메일·푸시 알림은 없다.

### 스캔·라벨
- R25 [2] 휴대폰 브라우저의 카메라로 QR/바코드를 스캔한다. 스캔 결과는 품목(SKU 일치, 없으면 바코드 일치)이나 위치(코드 일치)로 해석되어 해당 상세로 이동한다. 해석되지 않으면 안내 메시지를 보인다.
- R26 [2] 입고·출고·이동·조정 입력 화면의 품목·위치 칸에 스캔 버튼이 있고, 스캔하면 칸이 채워진다.
- R27 [2] 품목 라벨은 SKU를, 위치 라벨은 위치 코드를 담은 QR을 인쇄용 화면으로 만들어 브라우저 인쇄로 출력한다. 여러 개를 한 번에 선택해 인쇄할 수 있다.

### 엑셀
- R28 [1] 가져오기 엑셀(.xlsx)은 시트 "위치"(코드*, 이름*, 상위코드)와 시트 "품목"(SKU*, 이름*, 바코드, 단위, 최소수량, 메모, 위치코드, 수량)으로 구성한다. 양식 파일을 내려받을 수 있다. 품목 시트는 품목×위치 한 쌍이 한 행이며, 같은 SKU가 여러 행에 나올 수 있다.
- R29 [1] 업로드하면 저장 전 미리보기가 보인다. 행마다 신규/갱신/오류가 표시되고 오류 행에는 사유가 보인다.
- R30 [1] 검사 항목은 필수값 누락, 바코드·SKU·위치 코드 중복 충돌, 존재하지 않는 위치 코드/상위 코드, 정수가 아니거나 음수인 수량, 같은 SKU의 이름 불일치, 위치 순환이다. 오류가 하나라도 있으면 가져오기가 실행되지 않는다(전체 거절).
- R31 [1] 같은 SKU가 이미 있으면 품목 정보(이름, 바코드, 단위, 최소수량, 메모)만 갱신한다. 신규 품목×위치 조합에만 수량을 "초기/가져오기" 입고 이력으로 기록한다. 수량이 이미 있는 조합의 수량 열은 무시하고 미리보기에 "수량 무시됨"으로 표시한다.
- R32 [1] 가져오기 실행은 한 트랜잭션이다. 중간에 실패하면 아무것도 반영되지 않는다. 행 수는 5,000행 이하이다.
- R33 [1] 내보내기 엑셀은 시트 "현재 재고"(SKU, 이름, 위치경로, 위치코드, 수량, 단위)와 시트 "이력"(일시(KST), SKU, 이름, 위치경로, 유형, 증감, 사유, 작업자)로 구성한다.

### 공통
- R34 [1] 화면은 한국어이고 시각은 KST로 표시한다. 360px 너비 휴대폰에서 가로 스크롤 없이 모든 1차 기능을 쓸 수 있다.
- R35 [1] 입고·출고·이동 입력 화면은 모바일에서 품목·위치를 선택하고 수량을 입력해 제출하는 데 화면 전환 없이 한 화면에서 끝난다.

## Design
**구성** Next.js(App Router) 웹앱을 Vercel에 배포하고, Supabase의 Postgres·인증·저장소를 쓴다. 브라우저는 Supabase 클라이언트로 읽기를 하고, 수량을 바꾸는 모든 쓰기는 Postgres 함수(RPC)를 통한다.

**테이블**
- `profiles(id → auth.users, display_name, role)`
- `locations(id, parent_id, code, name, active)` — code는 소문자 변환 유일 인덱스
- `items(id, sku, name, barcode, unit, min_qty, memo, photo_path, active)` — sku·barcode는 소문자 변환 유일 인덱스(바코드는 null 허용)
- `stock(item_id, location_id, qty)` — 기본키 (item_id, location_id), `check (qty >= 0)`
- `movements(id, item_id, location_id, type, delta, reason, group_id, reverses_id, created_by, created_at)` — type은 receive/issue/transfer_out/transfer_in/adjust/import, `reverses_id` 유일

**쓰기 경로** `stock`과 `movements`는 클라이언트 직접 쓰기를 RLS로 막는다. RPC 함수가 이력 추가와 `stock` 갱신을 한 트랜잭션으로 한다. `movements`에는 update·delete 권한과 트리거를 두지 않는다. 음수는 `check` 제약이 최종 방어선이고, RPC는 먼저 검사해 읽기 쉬운 오류 메시지를 낸다. 동시 입력은 `stock` 행 잠금(`for update`)으로 직렬화한다.

**RPC** `record_receive`, `record_issue`, `record_transfer`, `record_adjust`, `reverse_movement`, `import_apply(payload)`.

**엑셀** 파싱과 검증은 서버(Route Handler)에서 한다. 미리보기 응답은 행별 상태와 사유를 담고, 확정 요청이 `import_apply`를 호출한다. 내보내기는 서버에서 .xlsx를 만들어 내려준다. 라이브러리는 plan에서 정한다.

**화면(경로)** `/login`, `/`(대시보드), `/items`, `/items/new`, `/items/[id]`, `/locations`, `/locations/[id]`, `/move`(입고·출고·이동·조정 탭), `/history`, `/import-export`. 2차에 `/scan`, `/labels`, `/stocktake`, `/settings/users`를 더한다.

**스캔·라벨 [2]** 브라우저 카메라 API로 스캔하고 QR은 클라이언트에서 생성한다. 카메라는 HTTPS에서만 동작하며 Vercel 배포는 충족한다.

**권한 [2]** RLS 정책을 `profiles.role`로 분기한다. 1차 스키마에 role 컬럼과 첫 사용자를 관리자로 지정하는 절차를 미리 넣는다.

**규모 가정** 품목 5,000개 이하, 최상위 위치 1~3개, 이력 수만 건. 목록은 서버 쪽 페이지네이션(50건)으로 한다.

## Decisions
- D1 품목·창고 수(미결이었음) — 위 규모 가정으로 설계한다. 가정을 넘기면 페이지네이션·인덱스를 다시 본다. 사용자가 실제 수치를 알려주면 갱신한다.
- D2 엑셀 열 구성(미결이었음) — 기존 자료의 형식을 확인하지 못했으므로 R28의 고정 양식을 쓴다. 기존 자료는 이 양식으로 옮겨서 가져온다. 열 이름이 다른 자료를 직접 읽는 기능은 만들지 않는다.
- D3 권한 차이(미결이었음) — R4의 안(작업자는 품목·위치 편집, 가져오기, 사용자 관리 불가)으로 한다. 2차 착수 전에 사용자가 확인한다.
- D4 SKU 자동 부여 규칙 — 미결. 지금은 직접 입력만 만들고 SKU는 자유 문자열이다. 자동 부여는 나중 기능이라 형식을 정하지 않는다. 대신 SKU 칸이 비어 있어도 되는 확장은 막지 않도록 `not null`만 걸어 둔다.
- D5 위치 코드는 트리 전체에서 유일하다. 근거는 QR/스캔이 코드 하나로 위치를 특정해야 하기 때문이다.
- D6 이동은 이력 두 행(transfer_out, transfer_in)이다. 근거는 위치별 이력 조회와 수량 합 검증(R20)을 한 규칙으로 하기 위해서이다.
- D7 가져오기는 오류가 있으면 전체 거절한다. 근거는 부분 반영이 어느 행이 들어갔는지 추적을 어렵게 하기 때문이다. 요구가 "오류 행 표시"이므로 일부만 반영하는 방식은 만들지 않는다.
- D8 `stock`은 이력 합의 캐시이다. 근거는 조회 성능이고, 일치는 RPC 단일 쓰기 경로와 R20의 검증 쿼리로 보장한다.

## Conflicts
- C1 intent는 실사 조정을 2차로 두면서 음수 출고를 막고 "수량이 틀리면 실사 조정으로 먼저 맞춘다"고 한다. 1차에 조정 수단이 없으면 수량이 실제보다 적을 때 입고로만, 많을 때는 정정 외에 줄일 방법이 없다. 제안은 R21로 1차에 단건 조정 입력(품목·위치·실제 수량·사유)만 넣고, 일괄 실사 화면(R22)만 2차로 두는 것이다. 이는 intent의 1차 범위에 없는 항목을 추가하므로 사용자 확인이 필요하다.
- C2 intent는 부족 품목 표시를 2차로 두지만 최소 수량 필드는 품목 필드에 포함한다. 1차에서는 최소 수량을 저장·편집만 하고 표시는 2차(R24)로 한다. 충돌은 아니고 해석을 적어 둔다.
- 그 외 CLAUDE.md 규칙과 충돌하는 항목은 없다.

## Acceptance
1. 로그인 없이 `/items` 주소를 열면 로그인 화면으로 간다. 로그인 화면에 가입 링크가 없다.
2. 품목 A를 입고 10개(위치 X)로 입력하고 위치 Y로 4개 이동하면 품목 상세에 X 6, Y 4, 합계 10이 보이고 이력에 3행(입고 1, 이동 2)이 보인다.
3. X에서 7개 출고를 입력하면 오류가 나고 수량·이력이 그대로이다.
4. 방금 한 입고를 정정하면 반대 이력이 생기고 수량이 맞게 바뀐다. 같은 입고를 다시 정정하면 거절된다. 이력 행을 수정·삭제하는 화면도 API도 없다.
5. 수량이 남은 품목과 위치는 보관할 수 없고, 수량이 0이면 보관되어 선택지에서 사라진다.
6. SKU 또는 바코드를 대소문자만 다르게 중복 등록하면 거절된다.
7. 조정 입력으로 X의 실제 수량을 5로 입력하면 사유 없이는 저장되지 않고, 사유를 쓰면 -1 조정 이력이 남는다.
8. 양식 엑셀을 내려받아 위치 3개, 품목 5개를 채워 업로드하면 미리보기에 행별 신규가 보이고, 확정하면 "초기/가져오기" 입고 이력이 생긴다. 같은 파일을 다시 올리면 모든 수량이 "수량 무시됨"으로 표시되고 수량이 변하지 않는다.
9. 오류 행(없는 위치 코드, 음수 수량 등)이 섞인 파일은 미리보기에서 사유와 함께 표시되고 확정 버튼이 막힌다.
10. 내보낸 엑셀에 "현재 재고"와 "이력" 시트가 있고 값이 화면과 같으며 시각이 KST이다.
11. 360px 너비에서 1차 모든 화면에 가로 스크롤이 없고, 입고·출고·이동이 한 화면에서 끝난다.
